# regex-testing Specification

## Purpose

正则测试器提供结构化的正则表达式输入与实时匹配能力，以双区布局将编辑区与高亮预览区分离，并在底部展示匹配结果列表；通过 Web Worker 隔离执行并设置超时防护，杜绝灾难性回溯冻结界面；辅以速查抽屉、字符计数提示与渲染上限保护，兼顾功能完整性与界面流畅度。
## Requirements
### Requirement: 结构化正则输入

正则测试器 SHALL 提供结构化的 pattern 输入：以 `/ [pattern] / [flags]` 形式呈现，pattern 为等宽字体单行输入框，flags（`g` `i` `m` `s` `u` `y`）为可切换的方块，并通过视觉与程序化状态表示是否启用。

#### Scenario: 输入 pattern 与切换 flag
- **WHEN** 用户在 pattern 输入框键入 `\d+` 并点亮 `g` 方块
- **THEN** 系统以 `new RegExp('\\d+', 'g')` 的等价配置执行匹配

#### Scenario: Flag 名称与状态可访问
- **WHEN** 用户通过键盘或辅助技术访问任一 flag
- **THEN** 控件暴露该 flag 的完整含义、当前开启/关闭状态，并可通过 Enter 或 Space 切换

#### Scenario: 非法正则就地报错
- **WHEN** 用户输入语法非法的 pattern（如未闭合分组 `(\d`）
- **THEN** 系统在 pattern 行下方以错误文字显示原因，且不抛出未捕获异常、不冻结界面

### Requirement: 实时匹配

正则测试器 SHALL 在 pattern、flags 或测试文本变化时自动重新匹配（debounce 约 250ms），无需用户手动点击触发。

#### Scenario: 编辑触发重新匹配
- **WHEN** 用户修改 pattern 或测试文本
- **THEN** 系统在停止输入约 250ms 后自动重新计算并刷新高亮与结果列表

#### Scenario: 空 pattern 清空结果
- **WHEN** pattern 为空
- **THEN** 系统不产生任何匹配，高亮预览显示原文且结果列表为空

### Requirement: 编辑与高亮分离的双区布局

正则测试器 SHALL 以左右双区呈现测试文本：左为可编辑输入区，右为只读高亮预览区，预览区将命中片段染色显示。

#### Scenario: 匹配片段染色
- **WHEN** pattern 在测试文本中存在命中
- **THEN** 高亮预览区在原文上下文中对每处命中片段染色，未命中文本保持普通样式

#### Scenario: 多捕获组区分色
- **WHEN** pattern 含多个捕获组且命中
- **THEN** 预览区对整体匹配与各捕获组使用可区分的颜色

### Requirement: 匹配结果列表

正则测试器 SHALL 在底部展示匹配结果列表，逐条显示匹配序号、位置区间、整体匹配值，以及各捕获组的值；并显示匹配总数。

#### Scenario: 列出全部匹配
- **WHEN** pattern 以 global 配置命中多处
- **THEN** 结果列表逐条列出每处匹配的序号、起止位置、匹配文本与各捕获组值，并显示匹配总数

#### Scenario: 结果与高亮双向联动
- **WHEN** 用户将鼠标悬停在结果列表的某一条
- **THEN** 高亮预览区中对应的那处匹配被加深或描边；反向悬停预览区某处匹配时，结果列表对应条目同样高亮

### Requirement: 速查抽屉

正则测试器 SHALL 提供可收起的右侧速查抽屉，包含三节：常用模式、语法元字符、flags 说明；抽屉展开时不遮挡主工作区。

#### Scenario: 点击常用模式填入 pattern
- **WHEN** 用户在速查抽屉「常用模式」中点击某一项（如「邮箱」）
- **THEN** 该模式被填入 pattern 输入框并立即触发匹配

#### Scenario: 点击语法元字符插入光标处
- **WHEN** 用户在「语法元字符」中点击某一项（如 `\d`）
- **THEN** 该片段被插入到 pattern 输入框当前光标位置

### Requirement: Worker 超时防护

正则测试器 SHALL 在 Web Worker 中执行正则匹配，并由主线程设置超时；超时未返回结果时 MUST 终止该 Worker、提示用户正则过于复杂，并保持主界面响应。

#### Scenario: 灾难性回溯不冻结界面
- **WHEN** 用户输入会导致灾难性回溯的 pattern（如 `(a+)+$`）配合触发性文本
- **THEN** 主线程在超时（约 1–2 秒）后终止 Worker，显示「正则过于复杂，已中止」提示，界面全程保持可交互

#### Scenario: 终止后可继续使用
- **WHEN** 一次匹配因超时被终止
- **THEN** 系统重建可用 Worker，用户随后修改 pattern 或文本仍能正常匹配

### Requirement: 测试文本长度提示

正则测试器 SHALL 显示测试文本的字符计数与长度上限；接近或超过上限时给出可见提示。

#### Scenario: 字符计数与超限提示
- **WHEN** 测试文本字符数接近设定上限
- **THEN** 系统在文本区显示形如 `当前 / 上限` 的计数，并在接近或超出上限时改变提示样式

### Requirement: 海量匹配渲染保护

正则测试器 SHALL 对预览高亮与结果列表的渲染条数设上限；命中数超过上限时仅渲染前 N 条并提示用户。

#### Scenario: 超量匹配截断显示
- **WHEN** 一次匹配命中数超过渲染上限
- **THEN** 系统仅渲染前 N 条匹配，并显示「仅显示前 N 条」之类的提示，界面保持流畅

### Requirement: 匹配结果与当前输入快照一致

正则测试器 SHALL 只将匹配位置、高亮和结果列表应用到生成该结果的 pattern、flags 与测试文本快照，不得把旧位置应用到已经变化的新输入。

#### Scenario: Debounce 等待期间输入已变化
- **WHEN** 用户修改测试文本但新一轮 Worker 请求尚未完成
- **THEN** 预览显示当前原文且不套用旧匹配位置，旧结果列表不再表现为当前结果

#### Scenario: 丢弃乱序 Worker 结果
- **WHEN** 早期请求晚于新请求返回
- **THEN** 系统忽略早期结果，并只允许与当前完整输入签名一致的结果更新高亮和列表

#### Scenario: 当前请求完成
- **WHEN** Worker 返回的 generation 和完整输入签名均与当前输入一致
- **THEN** 系统同时更新匹配计数、高亮、捕获组和结果列表

### Requirement: Regex 结果区空间可调

正则测试器 SHALL 允许桌面用户在合理范围内调整测试/预览区与结果列表的空间，并在紧凑宽度下回退为可读的上下结构。

#### Scenario: 指针调整结果区
- **WHEN** 用户拖动测试区与结果区之间的分隔控件
- **THEN** 结果区高度在设定最小值和最大值之间变化，测试输入与 pattern control 保持可用

#### Scenario: 键盘调整与重置
- **WHEN** 键盘用户聚焦分隔控件
- **THEN** 用户可通过方向键调整尺寸，并通过可发现操作恢复默认比例

#### Scenario: 紧凑窗口自然堆叠
- **WHEN** Regex 可用空间不足以维持可调分栏
- **THEN** 测试/预览与结果列表按上下顺序显示，各区域具有可读最小高度且页面不产生不可控横向滚动
