## Context

现有实现已经具备 `NAV_GROUPS`、工具到分组的映射及分组最近工具记忆，但显示层级为左侧一级分组、顶部二级入口。一级分组仅有六个时，230px 左栏的内容密度过低；单工具分组又额外显示一行没有操作价值的二级入口。

此次改造限于 Renderer 的 workbench shell 和文件树呈现。必须保留十个工具的既有快捷键顺序、active tab 状态和各工具组件的内部状态；不得改变 Electron IPC、Agent Workshop 或文件系统行为。

## Goals / Non-Goals

**Goals:**

- 用一行顶部全局导航承载六个一级分组，降低持久占用的横向宽度。
- 对有多个工具的分组展示 168px 左右的上下文导航；单工具分组不占用该区域。
- 让一级/二级点击、数字快捷键与循环快捷键共用 `setActiveTab`，并保存每个分组最近选择的工具。
- 让编辑器文件树以稳定宽度、清晰缩进和连接线表达目录层级。
- 在深色、浅色和窄窗口下保持可读、可点击与无重叠的布局。

**Non-Goals:**

- 不更改工具分组、十个工具的快捷键编号或各工具的业务状态。
- 不将工具内部的三级选择再移动到全局导航；它们仍由所属 tab 管理。
- 不引入新的依赖、窗口路由或持久化 schema 迁移。

## Decisions

### 顶部全局导航 + 条件化上下文侧栏

`Header.vue` 改为全宽 top bar，显示品牌和六个分组按钮。`App.vue` 将多工具分组的入口渲染为单独的左侧上下文栏，并在单工具分组时省略它。

备选方案是保留左侧一级栏并压缩至 icon rail；它能节省宽度，但一级分组只有六项且仍需要在内容区另放二级入口，无法消除用户指出的双重导航感。

### 使用现有数据模型维护单一导航状态

继续由 `NAV_GROUPS`、`TAB_TO_GROUP_KEY` 和 `TAB_BY_KEY` 提供导航数据。所有入口调用 `setActiveTab`；一级入口根据 `recentTabByGroup` 恢复最后使用的子工具。该做法避免对快捷键、状态栏和页面可见性添加并行状态。

### 三级选择留在工具内容区

Encode、Text 和 Generator 的内部选择保持横向、紧凑的页面内工具栏。这些是当前 tab 的功能模式而不是全局工作台目的地；放进全局左栏会制造第三层持久导航。

### 文件树用结构线表达目录关系

树节点维持原有懒加载和点击逻辑。仅调整视觉：默认宽度控制在约 240px、每层 18px 缩进、子层连接线、展开/折叠文件夹图标及当前项状态。此选择比增加面板边框更直观，也不影响树的数据模型。

## Risks / Trade-offs

- [顶部空间增加] → 全局栏限制为一行，工具标题保留在 52px context bar；不再为单工具分组渲染二级行。
- [窄窗口容不下六个 label] → 顶部导航允许横向滚动，并在中等宽度收缩品牌文案，避免压缩主内容区。
- [键盘切换与最近项不同步] → 只通过 `setActiveTab` 更新最近项，数字和循环快捷键也调用该函数。
- [文件树线条造成视觉噪声] → 使用低对比度 token，仅在有子层的结构区显示。

## Migration Plan

1. 在 Renderer 内替换 shell 布局，并移除旧的一级导航收起状态。
2. 保留 `recentTabByGroup` 存储字段；旧配置不含该字段时继续回退到默认工具。
3. 通过单测、构建和 Electron 深浅主题截图验证；出现回归时可回退到该功能分支之前的 commit，不影响用户数据或主进程。
